# ChatGPT Prompt Engineering Experiments

A portfolio-ready collection of small Python experiments demonstrating how prompt design changes the behavior, structure, and usefulness of responses generated by ChatGPT-style language models.

This repository explores five practical prompt engineering workflows:

- **Summarizing** — condensing product reviews for different business audiences
- **Inferring** — extracting sentiment, emotions, topics, and structured metadata from text
- **Transforming** — translating, rewriting, converting formats, and proofreading text
- **Iterative prompt development** — refining prompts step by step until the output is clearer and more production-ready
- **Pizzeria chatbot** — using a system prompt and conversation history to build a simple terminal-based ordering assistant

The project is intentionally organized into small, focused modules so each prompting technique can be inspected, run, compared, and extended independently.

---

## Why This Project Exists

Prompt engineering is not only about asking a model a question. It is about designing instructions that reliably guide the model toward the right format, audience, level of detail, and behavior.

This repository demonstrates that idea through hands-on examples. Each module shows how small changes in a prompt can produce more useful outputs for tasks such as summarization, extraction, translation, tone rewriting, structured formatting, and multi-turn chatbot behavior.

## Modules

### 1. Summarizing

The `summarizing` module explores how the same product review can produce different summaries depending on the objective.

The example review is about a panda plush toy. The prompt versions ask the model to create a general summary, focus on shipping and delivery, focus on price and value, and extract delivery-related facts instead of summarizing the full review.

| Version | Prompt Goal                           | Output Focus                     |
| ------- | ------------------------------------- | -------------------------------- |
| v1      | Summarize in at most 30 words         | General review summary           |
| v2      | Summarize for the shipping department | Delivery-related details         |
| v3      | Summarize for the pricing department  | Price and perceived value        |
| v4      | Extract instead of summarize          | Shipping and delivery facts only |

Standalone documentation: [`summarizing/README.md`](summarizing/README.md)

---

### 2. Inferring

The `inferring` module demonstrates how prompts can infer meaning from unstructured text and return concise or structured outputs.

It uses a lamp review and a short news-style story about public-sector employee satisfaction. The prompts cover sentiment classification, emotion extraction, anger detection, product and brand extraction, multi-task JSON-style extraction, topic inference, and topic alert matching.

| Version | Task                             | Example Output                                          |
| ------- | -------------------------------- | ------------------------------------------------------- |
| v1      | Sentiment classification         | `positive`                                              |
| v2      | Emotion extraction               | `satisfied, grateful, pleased, appreciative, impressed` |
| v3      | Anger detection                  | `no`                                                    |
| v4      | Product and brand extraction     | `{ "Item": "lamp", "Brand": "Lumina" }`                 |
| v5      | Multi-task structured extraction | Sentiment, anger, item, and brand                       |
| v6      | Topic inference                  | Government survey, employee satisfaction, NASA, etc.    |
| v7      | Topic alert matching             | `nasa: 1`, `employee satisfaction: 1`                   |

Standalone documentation: [`inferring/README.md`](inferring/README.md)

---

### 3. Transforming

The `transforming` module explores prompts that ask the model to rewrite or convert input into a different language, tone, structure, or format.

Prompt examples include English-to-Spanish translation, language detection, multi-language translation, formal and informal translation, slang-to-business-letter rewriting, dictionary-to-HTML conversion, and proofreading.

| Version | Task                                                     |
| ------- | -------------------------------------------------------- |
| v1      | Translate English to Spanish                             |
| v2      | Detect the language of a phrase                          |
| v3      | Translate into French, Spanish, and English pirate style |
| v4      | Translate using formal and informal Spanish forms        |
| v5      | Convert slang into a business letter                     |
| v6      | Convert a Python dictionary into an HTML table           |
| v7      | Proofread and correct a product review                   |

Standalone documentation: [`transforming/README.md`](transforming/README.md)

---

### 4. Iterative Prompt Development

The `iterative` module demonstrates the process of improving a prompt across multiple versions.

The task is to generate a product description for a retail website using a technical chair specification sheet. Each prompt version adds a stronger requirement, such as a word limit, audience targeting, product IDs, HTML formatting, and a dimensions table.

| Version | Prompt Improvement                             | Purpose                                                 |
| ------- | ---------------------------------------------- | ------------------------------------------------------- |
| v1      | Basic product description prompt               | Generate an initial marketing description               |
| v2      | Add a 50-word limit                            | Control verbosity                                       |
| v3      | Add target audience and product ID requirement | Make the response more relevant for furniture retailers |
| v4      | Require HTML output and a dimensions table     | Produce website-ready structured content                |

Standalone documentation: [`iterative/README.md`](iterative/README.md)

---

### 5. Pizzeria Chatbot

The `pizzeria-chatbot` module is a simple command-line ordering assistant for a pizza restaurant.

It uses a system prompt to define the bot's role, conversation style, menu, ordering rules, pickup-or-delivery flow, address collection, and payment collection. The chatbot keeps a running conversation context so each user message can be answered in relation to the previous turns.

The chatbot demonstrates:

- System prompt design
- Multi-turn conversation context
- Menu-aware assistant behavior
- Order clarification
- Pickup versus delivery handling
- Short, conversational responses

Standalone documentation: [`pizzeria-chatbot/README.md`](pizzeria-chatbot/README.md)

## Getting Started

### 1. Clone the repository

```bash
git clone https://github.com/your-username/ChatGPT-PromptEng.git
cd ChatGPT-PromptEng
```

### 2. Create a virtual environment

```bash
python -m venv .venv
source .venv/bin/activate
```

On Windows:

```bash
.venv\Scripts\activate
```

### 3. Install dependencies

```bash
pip install openai python-dotenv
```

### 4. Configure environment variables

Create a `.env` file in the project root:

```env
OPENAI_API_KEY=your_api_key_here
OPENAI_MODEL=your_preferred_model_here
```

`OPENAI_MODEL` is optional, but it is useful if you want to choose a model available to your OpenAI account.

### 5. Run an experiment

Run any module from the project root:

```bash
python summarizing/main.py
python inferring/main.py
python transforming/main.py
python iterative/main.py
python pizzeria-chatbot/chatbot.py
```

For the chatbot, type `bye` to end the conversation.

Most experiment modules follow this pattern:

```python
from data import PROD_REVIEW

prompt = prompt_v1(PROD_REVIEW)
response = get_completion(prompt)
print(response)
```

This keeps the input data, prompt templates, model client, and execution script separate.

## Key Lessons Demonstrated

1. **Specific instructions produce more useful responses.**  
   Word limits, target audiences, and formatting rules help make outputs more relevant.

2. **The same input can serve different business goals.**  
   A review can be summarized for general understanding, shipping feedback, or pricing analysis.

3. **Structured output requires explicit formatting instructions.**  
   JSON-like responses and HTML tables are easier to reuse when the prompt clearly asks for them.

4. **Prompt iteration improves quality.**  
   A first prompt may work, but refined prompts are often more concise, specific, and production-ready.

5. **System prompts shape assistant behavior.**  
   The pizzeria chatbot shows how a system message can define role, tone, rules, and task flow.
