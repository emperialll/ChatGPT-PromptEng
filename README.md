# ChatGPT Prompt Engineering Experiments

A hands-on prompt engineering project exploring how different prompt strategies affect the behavior, structure, and usefulness of responses generated by a large language model.

This repository contains small, focused Python experiments for four common prompt engineering workflows:

- **Summarizing**: condensing product reviews with different business focuses
- **Inferring**: extracting sentiment, emotions, topics, and structured metadata
- **Transforming**: translating, changing tone, converting formats, and proofreading text
- **Iterative prompt development**: improving a prompt step by step until the output becomes more useful and production-ready

The goal of this project is to demonstrate practical prompting techniques through clear examples, versioned prompts, and saved model outputs.

---

## Project Overview

This project was built as a learning and experimentation repo for understanding how prompt wording, constraints, audience context, formatting requirements, and task framing influence LLM output.

Each module follows the same general pattern:

1. Define sample input data in `data.py`
2. Define prompt versions in `prompts.py`
3. Send each prompt to the model through `llm_client.py`
4. Run all prompt versions from `main.py`
5. Store representative responses in the `outputs/` folder

This makes the repository easy to inspect, run, compare, and extend.

## Modules

### 1. Summarizing

The `summarizing` module explores how the same product review can produce different summaries depending on the business objective.

The source text is a short ecommerce review about a panda plush toy. The prompt versions test different summary goals:

| Version | Prompt Goal | Output Focus |
| --- | --- | --- |
| v1 | Summarize in at most 30 words | General review summary |
| v2 | Summarize for the shipping department | Delivery-related details |
| v3 | Summarize for the pricing department | Price and perceived value |
| v4 | Extract instead of summarize | Shipping and delivery facts only |

**Example output:**

```text
Arrived a day earlier than expected.
```

This module demonstrates that changing a single instruction, such as the target department or whether the task is to “summarize” versus “extract,” can significantly change the usefulness of the response.

---

### 2. Inferring

The `inferring` module demonstrates how prompts can be used to infer meaning from unstructured text.

It uses two input examples:

- A customer review for a lamp
- A short news-style story about employee satisfaction in government departments

Prompt versions include:

| Version | Task | Example Output |
| --- | --- | --- |
| v1 | Sentiment classification | `positive` |
| v2 | Emotion extraction | `satisfied, grateful, pleased, appreciative, impressed` |
| v3 | Anger detection | `no` |
| v4 | Product and brand extraction | `{ "Item": "lamp", "Brand": "Lumina" }` |
| v5 | Multi-task structured extraction | Sentiment, anger, item, and brand |
| v6 | Topic inference | Government survey, employee satisfaction, NASA, etc. |
| v7 | Topic alert matching | `nasa: 1`, `employee satisfaction: 1` |

This module shows how prompt engineering can turn free-form text into structured, machine-readable information.

---

### 3. Transforming

The `transforming` module explores text transformation tasks where the model rewrites or converts input into a new language, tone, structure, or format.

Prompt versions include:

| Version | Task |
| --- | --- |
| v1 | Translate English to Spanish |
| v2 | Detect the language of a phrase |
| v3 | Translate to French, Spanish, and English pirate style |
| v4 | Translate using formal and informal Spanish forms |
| v5 | Convert slang into a business letter |
| v6 | Convert a Python dictionary into an HTML table |
| v7 | Proofread and correct a product review |

**Example use cases demonstrated:**

- Localization
- Tone rewriting
- Business communication
- Data-to-HTML conversion
- Grammar correction

This module highlights how LLMs can be used as flexible text transformation tools when prompts clearly define the desired target format.

---

### 4. Iterative Prompt Development

The `iterative` module demonstrates one of the most important prompt engineering practices: improving a prompt through repeated refinement.

The task is to generate a product description for a retail website using a technical chair specification sheet.

| Version | Prompt Improvement | Purpose |
| --- | --- | --- |
| v1 | Basic product description prompt | Generate an initial marketing description |
| v2 | Add a 50-word limit | Control verbosity |
| v3 | Add target audience and product ID requirement | Make the response more relevant for furniture retailers |
| v4 | Require HTML output and a dimensions table | Produce website-ready structured content |

The final version produces HTML with:

- A product description inside a `<div>`
- A product dimensions table
- Measurements converted to inches
- Product IDs included in the response

This module demonstrates that prompt quality often improves through deliberate iteration rather than a single attempt.

## Getting Started

### 1. Clone the repository

```bash
git clone https://github.com/your-username/ChatGPT-PromptEng.git
cd ChatGPT-PromptEng
```

Replace `your-username` with your GitHub username.

### 2. Create and activate a virtual environment

```bash
python -m venv .venv
source .venv/bin/activate
```

On Windows:

```bash
python -m venv .venv
.venv\Scripts\activate
```

### 3. Install dependencies

```bash
pip install openai python-dotenv
```

Optional: create a `requirements.txt` file for easier setup:

```text
openai
python-dotenv
```

Then install with:

```bash
pip install -r requirements.txt
```

### 4. Configure environment variables

Create a `.env` file in the project root:

```env
OPENAI_API_KEY=your_api_key_here
OPENAI_MODEL=your_preferred_model_here
```

The project reads the API key and optional model name from environment variables.

### 5. Run an experiment

Run any module from the project root:

```bash
python summarizing/main.py
python inferring/main.py
python transforming/main.py
python iterative/main.py
```

Each script prints the response for every prompt version in that module.

## Example Workflow

A typical experiment follows this flow:

```python
from data import PROD_REVIEW
from prompts import prompt_v1
from llm_client import get_completion

prompt = prompt_v1(PROD_REVIEW)
response = get_completion(prompt)
print(response)
```

The prompt is defined separately from the input data, making it easy to compare prompt versions without changing the core execution logic.

## Key Lessons Learned

This project demonstrates several practical prompt engineering lessons:

1. **Specific instructions produce more useful responses.**  
   Adding word limits, target audiences, and formatting rules improves output quality.

2. **The same input can support different business goals.**  
   A product review can be summarized for shipping, pricing, or general customer feedback.

3. **Structured output requires explicit formatting instructions.**  
   Asking for JSON-like responses or HTML tables makes the output easier to reuse programmatically.

4. **Prompt iteration is essential.**  
   Initial prompts often work, but refined prompts are more precise, concise, and production-ready.

5. **LLMs are useful for both language understanding and language transformation.**  
   The examples include sentiment analysis, extraction, translation, rewriting, and format conversion.

## Notes for Running Locally

- Make sure your `.env` file is not committed to GitHub.
- Keep `.env` listed in `.gitignore` to avoid exposing API keys.
- If you change model names, update the `OPENAI_MODEL` value in your `.env` file.
- If a module raises an import or name error, check that variable names in `data.py` and `main.py` match exactly.
